# QMD Architecture and Retrieval Guide

This document explains the role of `@tobi/qmd` within the code investigation ecosystem, how it relates to Capn and Waymark, and why retrieval engines and in-flight continuity ledgers serve complementary purposes.

---

## 1. What is QMD?

`@tobi/qmd` is an on-device hybrid search and retrieval engine developed by Tobi Lütke. It is engineered for local developer agents and tools that need high-precision context retrieval over local repositories and Markdown knowledge bases without relying on external cloud APIs.

### Core Mechanisms

- **Hybrid Lexical and Vector Search:** Combines SQLite FTS5 BM25 keyword matching with local vector embeddings generated by local GGUF models.
- **Hypothetical Document Embeddings (HyDE):** Expands developer questions into synthetic answer hypotheses to improve semantic embedding alignment.
- **Reciprocal Rank Fusion (RRF):** Merges lexical and semantic ranking signals to ensure both exact keyword hits (symbol names, function identifiers) and conceptual matches are ranked fairly.
- **Local Cross-Encoder Reranking:** Applies local small-model reranking to top candidates to eliminate retrieval false positives.
- **AST-Aware Code Chunking:** Parses code files into syntax trees to produce clean chunks along function, method, and class boundaries rather than naive character or line offsets.
- **MCP Surface:** Exposes standard Model Context Protocol endpoints (`query`, `get`, `multi_get`).

## 2. The Separation of Responsibilities

A common question when evaluating agent tooling is: *"If I use QMD for local code search, why do I need Waymark?"*

The answer lies in the architectural division between **stateless discovery**, **in-flight continuity**, and **long-term storage**:

```text
+-------------------------------------------------------------+
| 1. DISCOVERY & SEARCH: QMD (@tobi/qmd)                      |
|    - Questions: "Where is authentication handled?"          |
|    - Mechanism: Hybrid BM25 + GGUF vector + AST chunking   |
|    - Output: Ranked candidate code snippets (1,500-4,000 t) |
+-------------------------------------------------------------+
                              |
                              v (Agent inspects & verifies)
+-------------------------------------------------------------+
| 2. IN-FLIGHT CONTINUITY: Waymark (paragon-ux/waymark)       |
|    - Questions: "What have I proven so far in this task?"   |
|    - Mechanism: Hashed spans, relocation scan, NDJSON log   |
|    - Output: Bounded resume packet (<2,048 B / ~216 tokens) |
+-------------------------------------------------------------+
                              |
                              v (Trajectory completed & sealed)
+-------------------------------------------------------------+
| 3. LONG-TERM MEMORY: Capn (CyrusNuevoDia/capn-hook)         |
|    - Questions: "Has anyone solved this in a prior session?"|
|    - Mechanism: Sealed Q&A knowledge bases indexed by QMD   |
|    - Output: Reusable charted answers                       |
+-------------------------------------------------------------+
```

---

## 3. Why QMD Alone Cannot Solve In-Flight Continuity

QMD is an indexer and retrieval tool. It is intentionally stateless across agent turns:

1. **No Relocation Tracking:** If an agent refactors code or if another process edits a file during a long investigation, QMD does not know that line 45 has relocated to line 68. Waymark actively validates line anchors against Git HEAD and sliding windows (`MOVED` vs `STALE`).
2. **No Causal Provenance:** QMD returns candidate snippets. It does not record *which* candidate was confirmed, in what sequence, or what specific deduction the agent made.
3. **Context Cost Across Compaction:** When an LLM hits context compaction mid-task:
   - *Without Waymark:* The agent must re-issue QMD queries and re-read top candidate files, consuming 1,500 to 4,000 tokens of fresh context and re-evaluating false positives.
   - *With Waymark:* The agent calls `waymark_resume` and receives only the verified breadcrumb trail in ~216 tokens (<820 bytes).

## 4. Context Budgeting and Integration Patterns

When configuring an agent with both QMD and Waymark:

1. **Step 1 (Check Prior Knowledge):** Query Capn memory (`capn_ask`). If charted memory exists (backed by QMD index), adopt the answer without searching.
2. **Step 2 (Explore Candidates):** If uncharted, call QMD `query` to surface top AST code chunks.
3. **Step 3 (Verify and Note):** Inspect the candidate. When a code block provides verified evidence, immediately call `waymark_note({ trajectory_id, path, start_line, end_line, inference })`.
4. **Step 4 (Compaction Recovery):** If context compaction fires, call `waymark_resume`. Do not re-run QMD discovery for already-verified hops.
5. **Step 5 (Finalize):** Call `waymark_complete` to archive the trajectory and chart the conclusion into Capn, where QMD indexes it for future sessions.
